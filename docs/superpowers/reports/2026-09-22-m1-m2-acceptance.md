## 阻断项

### R1 / P1：同一账号的旧结果可覆盖较新凭证

位置：`UsageValidation.ps1:136` 的 `Assert-CredentialIdentity`，以及 `AiUsageWidget.ps1:919` 的 `Save-KimiAuth` 等调用路径。

账号 ID 相同即返回成功，refresh token 的变化不会阻止保存。多个写回路径也没有保留“发起刷新时的原始版本”；例如 Update-KimiToken 在调用 Save-KimiAuth 前已经把 Auth.Refresh 替换为响应的新值。因此不能只把身份判断改成简单 AND，必须明确原始版本与新结果。

复现：读取 A 的旧凭证后，将临时活动文件替换成同账号 A 的更新凭证，再调用真实 Save-KimiAuth。结果：`NewerCredentialPreserved=false`，更新凭证被迟到的 worker 结果覆盖；未知字段保留成功。探针仅替换了无关的快照持久化入口，活动 JSON 写入、锁和校验使用真实实现。

影响：同账号重新登录或外部 CLI 刷新后，旧 token 可能回写，损害后续登录连续性。

整改与复验：保留 ExpectedAccountId、原始 refresh/access 指纹或文件版本；锁内重新比较身份和版本，识别 account-changed 与 credential-stale；拒绝旧结果覆盖更新的活动凭证或快照。覆盖同账号重新登录、同账号两个刷新结果乱序返回及轮换后重复登记。

补充：`Save-ClineSnapshot` 在 `AiUsageWidget.ps1:1560` 传递的是 Auth.Refresh / currentAuth.Refresh，而 Cline 对象使用 RefreshToken；版本校验完善时必须同步修正该调用点。

### R2 / P1：Claude / Cline 保存失败仍返回刷新成功对象

位置：`AiUsageWidget.ps1:1712`、`AiUsageWidget.ps1:1911`。

Update-ClineToken 和 Update-ClaudeToken 捕获 Save-*Auth 的异常，只记日志，然后返回 Auth。日志使错误并非完全消失，但 worker 得不到持久化失败状态，仍可继续用新 token 获取用量并呈现成功。这不满足 M1“不会把失败写回记为成功”的验收标准。

复现：保留真实 Update-*Token，模拟刷新响应成功并令保存抛出 synthetic-disk-write-failed，两个入口均正常返回：`FailurePropagated=false`。

整改与复验：让保存失败向上抛出，或通过结构化状态明确返回“查询可用但凭证保存失败”并展示；覆盖磁盘拒绝、文件占用、DPAPI 不可用与临时文件清理。不得只增加日志后宣称通过。

### R3 / P1：M2 长期留存仍会被条数截断破坏

位置：`AiUsageWidget.ps1:4477` 的 Write-UsageHistory，以及趋势/预测中 Limit 2000 的读取。

复现：120 天、20 账号、每天每账号 10 条，共 24,000 条有效旧格式样本，文件为 1,932,000 字节。调用一次真实 Write-UsageHistory 后只剩 2,000 条，绝大部分历史被截断。

这不仅是缺少新配置，而是当前写入行为与 M2 至少 90 天原始历史目标直接冲突。报表即便能够渲染多月，也无法恢复已删除数据。

整改与复验：先版本化 schema 和双读，再按月存储、日期/容量保留与完整性标记；保留迁移源文件。用同样的 120 天/20 账号夹具验证归档、跨月导出、迁移幂等、容量上限和中断恢复；超过策略范围的数据可按明示规则淘汰。

### R4 / P1：预测没有隔离配额重置周期

位置：`UsageHistory.ps1:112` 的 Get-UsageForecast。

复现：日序列 90、95、5、15，其中 95→5 为周期重置。当前周期斜率应为每天 +10 个百分点；现有全序列拟合得到 -31.5，并返回 EtaHours=null。没有周期字段，无法区分重置、指标切换与正常变化。

整改与复验：记录窗口、周期/重置时间和有效采样状态，只对同一窗口同一周期拟合；样本不足明确不可估算。补 5 小时日内、额度调整、跨时区与缺失采样测试。

# AI Usage Widget M3 调度与扩展性验收

执行日期：2026-09-22。

## 目标与结论

M3 已完成静态供应商注册表、最多 3 个有界抓取 job、provider affinity、逐 job 结果应用、generation
隔离、错误分类退避和逐行状态保留。没有引入任意第三方插件执行。

## 静态供应商注册表

`WidgetProviders.ps1` 是供应商元数据的静态白名单，集中记录：

- `Kind` / 显示名
- `Get-*RowData` worker 入口
- 用量页变量
- 凭证发现入口
- 依赖模块

启动脚本加载该模块，安装与发布包清单包含它。worker 一致性测试会检查主程序里的每个行类型都存在
注册项、注册项名称唯一、对应 row function 已注入 worker。

## 有界调度

- `Split-WidgetProviderRows` 按供应商分组，再按账号数均衡到最多 3 个 job。
- 同一供应商不会拆到多个并发 job，避免同供应商内多个账号同时请求。
- runspace pool 常驻复用，job 上限固定为 3，不接受任意并发配置。
- 每个 job 独立超时 3 分钟；已完成 job 立即转换并应用结果，不再等整批结束。
- 每次刷新递增 generation；配置或账号变化后，旧 generation 的结果会丢弃。
- 手动刷新与 F5 使用 `-Force` 跳过退避；定时刷新仍尊重退避。

## 错误与行状态

错误分类为：

| 分类 | 典型条件 | 基础退避 |
| --- | --- | --- |
| `auth` | 401 / 403 / 登录过期 | 300 秒 |
| `rate-limit` | 429 / rate limit | 60 秒 |
| `timeout` | 请求超时 | 指数退避 |
| `parse` | bad payload / JSON / 解析错误 | 指数退避 |
| `network` | 其他网络或未知错误 | 指数退避与抖动，最高 900 秒 |

失败行保留上次成功值和成功时刻，并显示下次重试时间；行级错误不会被其他账号的成功状态掩盖。

## 已知边界

- 未执行真实账号下的 20 / 50 行压力、GUI 长时间运行和睡眠恢复验收。
- job 内部仍按账号串行；同供应商的慢账号可能占用该 job，但不会阻塞其他 provider job。
- 本轮采用最多 3 个 job 和供应商亲和，未实现按指标动态扩张或复杂队列优先级。

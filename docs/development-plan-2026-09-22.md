## 2. 优先问题与证据

### P0：凭证写回的账号并发保护

`AiUsageWidget.ps1` 的 `Save-KimiAuth` 从当前凭证文件读取后直接替换 token，未在写回前重新匹配账号；`Save-ClaudeAuth` 和 `Save-ClineAuth` 使用之前读取的 Raw 序列化后覆盖。项目自己的文件锁无法保证外部 CLI 同样遵守。

推导出的风险场景：后台持有 A 账号旧凭证，用户已在 CLI 切到 B，A 的刷新结果随后写回当前凭证文件。需用可复现测试确认，不能把风险场景描述为已观察到的数据损坏。

处理：锁内重读，核对账号身份和刷新凭证版本，只更新目标字段；发现切换时保留当前登录，将结果写入 A 的快照。跨进程仍需尽量缩短检查到原子替换的窗口，明确不能让不合作的外部进程参与同一事务。

### P1：历史保留与报表目标矛盾

`Write-UsageHistory` 在文件超过 1 MB 后仅保留末尾 2,000 条；趋势读取也限制末尾 2,000 条。历史只在首次成功或百分比变化至少 0.05 时写入，余额数值未进入历史。

结果：保留天数随账号数与变化频率变化；静止用量可能整日没有样本；跨月对比未必有完整月份；余额服务会留下百分比占位记录。不能把这种历史描述为完整每日采样。

处理：按日期保留、分月文件、日内定时采样与变化采样结合；历史覆盖率显式展示；先保留旧文件可读，再引入版本化字段。

### P1：串行抓取导致整批等待

`Get-WorkerScriptSource` 中逐行串行调用；`Receive-BackgroundFetch` 在全部结束后统一应用，整轮超过 3 分钟终止。单 HTTP 默认 15 秒，加 5 秒硬超时余量，部分供应商还有刷新和额外请求。

风险：慢账号拖延其他结果显示；账号增加后更容易碰到整轮上限；终止整批时已经完成的结果也未必展示。

处理：有界并发、按账号提交结果、按供应商限速、过期结果隔离。先解决凭证写回，再引入并发。

### P1：统计表达需要准确

历史模型只有 `ts/id/pct`，没有配额窗口、重置周期、原始数量、限额、币种与数据状态。月度变化比较的是月末百分比差，不是月消费金额或请求量增长。预测对按天序列直接做线性拟合，未按配额重置周期切分。

处理：显式区分配额百分比、余额、无上限、未知状态；保留现有月末快照对比但准确命名；仅在具有可靠原始计数时计算消费量。跨重置周期不直接拟合，不以百分比差估算费用。

### P1：主程序扩展成本上升

主程序同时承担凭证适配、账号管理、网络、调度、UI 和历史写入。新增供应商仍需同步函数注入白名单、配置转发、switch 分派、菜单与安装清单。

处理：复用现有解析模块、SecureSnapshot、ApiKeyAuth，分步抽出 Provider 注册表、账号存储和调度模块；采用静态白名单，不引入任意插件执行机制。

### P2：账号体验、文档与发布一致性

- 多账号已有登记入口，但缺少统一的重命名、隐藏、移除快照、排序和状态管理界面。
- Copilot 的账号 ID 由 token 指纹生成；换 token 可能形成新身份。API-key 服务可以按密钥区分，OAuth 服务应优先使用稳定身份。
- `Get-UiScale` 缓存 DPI，没有拖到不同缩放显示器后的重算。
- 架构文档末尾仍称没有图表和跨月对比，与 0.15.0 实现矛盾；旧路线图开头的“6 个供应商、16 套测试”只是历史快照。
- Pages 工作流路径过滤没有包含提供版本号的主程序；只改版本号时不一定重建网页。
- Release 手工输入 tag 与默认 checkout 的 ref 缺少强绑定，发布前需要确认版本、提交、tag 和产物一致。
- 工作区存在 `%SystemDrive%/` 缓存目录和工具临时目录，需要查明来源、归类忽略，不能直接将所有未跟踪内容加入发布提交。

## 3. 实施原则

保持 Windows、PowerShell 5.1/7、WinForms、本地优先和运行时零第三方模块依赖。优先修复可靠性，再扩充供应商；不安排整体语言重写、云同步或复杂插件系统。

所有修改先追踪调用链：供应商发现 → 身份/凭证 → 请求 → 解析 → 行模型 → worker → UI → 历史/提醒 → 导出。接口变化同步更新打包清单、测试和文档。

### M1：多账号与凭证正确性，建议 0.16.0（4–6 日）

> 状态（2026-09-22）：已完成本轮实现与离线回归，包括同账号旧版本拦截和保存失败传播；
> 0.16.0 其余发布收口仍按本阶段验收执行。

1. 统一身份语义：ProviderId、AccountId、凭证来源与稳定行 ID；记录哪些供应商只能按密钥或 token 区分。
2. 抽取最小的公共凭证更新助手，复用现有锁与原子替换，不重复实现各家文件操作。
3. 实现写回前身份与版本匹配、只更新目标字段、临时文件 finally 清理；失败不得静默吞掉。
4. 为当前登录和离线快照分别定义刷新行为，保护未知 JSON 字段。
5. 处理 token 轮换后的账号连续性、重复登记与重新登录状态；有可靠身份才自动合并，无法证明时保留独立记录。
6. 完成 Cline 与新增多账号适配的 worker、配置、语言、安装包联动验收。

重点测试：A 抓取期间切到 B；A/B 同时刷新；CLI 修改其他字段；文件占用、写入失败、损坏快照、DPAPI 不可用；token 轮换后不串号；旧版本账号 ID 的迁移不错误归属。

验收：模拟切换后 B 文件保持 B 身份；A 结果只进入 A 快照；不会把失败写回记为成功；新旧账号都使用自身凭证。

### M2：数据留存与统计口径，建议 0.17.0（5–7 日）

> 状态（2026-09-22）：schema v2、月度归档、旧文件迁移、保留策略、有效采样和周期内预测已完成；
> 验收记录见 `docs/superpowers/reports/2026-09-22-m2-history-storage.md`。

1. 增加历史 schemaVersion，按需要记录 provider、accountId、metricType、window、cycle/resetAt、value、unit、used/limit、采样状态；缺失数据保持未知，不伪造。
2. 双读旧 `ts/id/pct` 与新格式；旧行无法可靠映射账号时显示为历史账号，不强行归并。
3. 分月存储，默认提供至少 90 天原始历史，可配置保留天数与容量上限；容量不足时明确显示历史不完整。
4. 变化采样之外增加可配置的定时有效采样，记录最近成功时间；运行中无变化与程序未运行可以区分。
5. 日汇总缓存复用现有聚合函数；长期报表读取归档，不只读最后 2,000 条。
6. 百分比、余额、无上限指标分别展示；月末百分点差准确命名，余额变化说明充值等因素会影响解释。
7. 预测只使用同一窗口和周期内的有效样本，采样不足显示无法估算；5 小时窗口使用适合的日内采样。
8. 安装器、卸载器、Scoop persist 和导出同步支持新的数据目录；迁移可重复执行并保留原文件。

重点测试：至少 4 个月/20 账号的合成数据；1 MB 边界；空月、重复、乱序、损坏行、时区、重置、额度调整、余额充值；写入中断恢复。

验收：四个月数据跨文件导出准确；不会因固定条数轮转丢失承诺范围；旧历史可读；余额不显示虚假 0% 趋势；跨周期不生成误导预测。

### M3：调度与扩展性，建议 0.18.0（4–6 日，依赖 M1）

> 状态（2026-09-22）：静态供应商注册表、有界并发 3、provider affinity、逐 job 结果应用、
> generation 隔离、错误分类退避和逐行状态保留已完成；压力与 GUI 长时间验收仍留作后续环境验证。

1. 抽出静态供应商注册表，集中名称、开关、页面、账号发现、抓取入口和依赖模块。
2. 分离抓取调度和 UI，将账号发现的文件扫描/快照同步逐步移出 UI 热路径。
3. 有界 worker 池，建议初始并发 3；同供应商限速、账号刷新锁，禁止无界并发。
4. 独立超时与逐账号结果应用；为每轮分配 generation，丢弃配置变化或账号移除后的旧结果。
5. 区分 401/403、429、网络超时和解析失败，支持可获得的 Retry-After、抖动退避；定义手动刷新是否跳过退避。
6. 行内保留上次成功值，并标明过期、最近成功、下次重试；整体状态不能用一次成功掩盖其他账号错误。
7. 记录无敏感信息的请求耗时、错误类型和排队时间，供本地诊断。

重点测试：20/50 行压力；单行持续超时；刷新中关闭窗口、切换账号/配置、休眠恢复；无重叠任务与资源泄漏。

验收：慢行不阻挡其他已完成结果显示；并发不超限；旧轮次结果不覆盖新状态；关闭后 worker 可回收。延迟和内存先测基线，再设性能门槛。

## 5. 排期与取舍

建议顺序：M0 → M1 → M2 → M3 → M4；M5 的发布一致性和统一测试入口提前穿插，其余随各里程碑验收。总计约 20–30 个有效开发日，预留 20% 缓冲后约 24–36 日。

近期只承诺 M0/M1，再依据实测数据调整后续估算。每阶段以独立可运行版本收口，不把全部优化打成一个大提交。

暂缓：没有可靠成功载荷的供应商、跨平台重写、云账号同步、自动登录/接管客户端会话、通过百分比猜测 token/费用、开放任意第三方脚本插件。

新增供应商准入：先有可用凭证来源和经脱敏的成功/失败载荷，再有解析、边界与集成测试，最后进入 UI 与发布包。现有文档中的外部接口结论需要在实际接入时重新核实。
